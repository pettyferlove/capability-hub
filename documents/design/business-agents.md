# 业务 Agent

`packages/hub-agents` 提供资源审计、反馈研判和发布审核助手。运行与 SSE 复用 [AI 框架](ai-framework.md)，证据由 Application 提供。

## 发起与权限

资源审计输入为 `{version_id}`，反馈研判为 `{version_id, feedback_id}`，不提交资源正文。提交、模型请求、工具执行、记录读取及 SSE 推送均重新核验账号、AI 权限和资源权限。反馈还须满足原有提交者或维护者可见规则，并匹配目标版本。候选沿用维护者与对应审核者的审查权限；封禁资源和撤销版本不接受研判。

自动排队、反馈关联和业务写入同事务提交。反馈详情优先展示可读的自动研判，再列出本人对该反馈发起的任务。触发时机、分派顺序和报告查看权限见 [Agent 执行与权限清单](ai-framework.md#当前操作与权限)。

## 自主取证

| 工具                | 能力与边界                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `resource_overview` | 类型、固定版本摘要、入口文件，不加载正文                                                         |
| `list_files`        | 分页目录、大小、SHA-256、可执行标记，每页最多 100 项                                             |
| `read_file`         | 固定版本按行读取；每次最多 200 行、24,000 字符；超过 512,000 字节或非 UTF-8 文本时明确返回不可读 |
| `search_files`      | 字面文本定位；每次检查 10 个文件的前 200 行，返回游标和未完整检查文件；引用前仍需显式读取        |
| `scan_findings`     | 固定版本的静态扫描状态、规则与发现项                                                             |
| `compare_release`   | 与当前发布比较新增、修改、删除文件，不隐式读取正文；基线权限独立核验                             |
| `mcp_declarations`  | MCP 安装选项、工具声明和描述 Schema                                                              |
| `review_warnings`   | 本次申请冻结扫描中的告警，每页 20 项，仅发布审核助手提供                                         |
| `review_changes`    | 本次申请与提交时发布基线的文件差异，每页 50 项，仅发布审核助手提供                               |
| `read_feedback`     | 目标反馈的观察、预期、复现、证据和建议，仅反馈研判提供                                           |

Skill 从 `SKILL.md` 开始，按引用读取其他文件；MCP 从 `server.json` 开始，检查安装、权限、变量、网络目的地和工具声明。未读取入口文件或目标反馈时不能形成报告。工具不接受任意版本、宿主路径、Shell 命令或网络 URL。资源与反馈是不可信证据，不能改变授权或系统指令。

候选内容的 `read_file` 按路径和请求行段记一条管理读取，`search_files` 每页记一条并逐文件复查权限。

此批 MCP 审计为静态审计，不连接声明远端、不安装软件包、不执行其中的工具，报告始终列明范围。框架独立提供的受信 MCP 只读工具接入不代表被审计资源通过了动态验证。

调查最多 64 个 Agent 步骤，仍受实例级请求、工具、时间、事件预算约束。预算由 [AI 框架](ai-framework.md) 统一定义。

## 报告与人工决定

报告区分材料中的陈述、已核实的事实和有条件的影响。发现可为空；关键证据不足以定级时用 `unknown`。已读内容能证明严重行为及触发条件时，应指出影响，不宣称事故已经发生。文件引用超出实际连续读取的行段会失败；引用有效不等于解释正确。

资源审计（`8`）区分固定版本的默认路径、可选行为和示例。风险报告与发布建议分开生成，各自修复格式，均通过后合成报告。反馈研判（`4`）按目标反馈核对上报观察与版本证据，区分故障、能力缺口和建议；不能定位时只提出影响判断的补证项。旧版任务须重新发起才能使用新规则。

资源审计和反馈研判先保存为 `assessment` 成果，再暂停为 `human-review`。发起人明确采纳或不采纳并填写可选意见；不采纳正常结束并保留记录。采纳审计不批准发布、不改变扫描状态，不代替告警接受理由或独立人工审核。

反馈研判对有维护权限的发起人提供可选写回：采纳后改为 `in_progress`，以人工意见或报告建议作为处理说明，不自动解决或关联修复版本。写回使用调查开始时的 feedback revision，恢复时重新检查权限；人工已更新则拒绝旧结果。业务更新和效果回执共用事务，恢复不重复写入。未勾选写回则不改反馈状态。

发布审核助手（`2`）依据申请冻结的基线、策略、内容摘要和扫描 ID 说明拟议分发变化。策略差异写入摘要，文件问题引用已读行段，告警疑问只关联本次查阅的 ID。只读简报保存在执行结果中，决定与逐条告警接受理由由审核员填写。

## 页面行为

校验、发布申请和反馈详情用停靠面板订阅目标任务。审核决定抽屉内嵌版本审计，提交者在审核页仅查看申请。审核员本人对相同版本和内容摘要采纳的建议自动带入空白审核意见；已填写的意见可手动追加建议。告警理由、审查确认及提交决定均由审核员填写或选择。收起不取消任务、不停止订阅、不丢失确认草稿。快速采纳沿用已填意见、交互修订和幂等键。反馈研判采纳后，同一修订的建议填入维护者的空白处理说明草稿，已有内容由维护者选择替换；保存后可在反馈详情顶部查看。没有活动任务且已配置模型时，可以按当前模型和资源目标重新发起。等待人工确认时加载完整报告和表单，回答后继续订阅。文件读取活动展示路径和请求行号。

资源审计建议分类、场景、前 8 个检索词和共享目的。按用户任务查 `publication_scenarios`，优先复用返回的 ID。用途明确且无匹配时才以同类资产可共用的任务短语起名，用途不明则建议未分类。发布页核对当前用户最近采纳的版本和内容摘要，保留手动编辑，关键词合并去重。待确认时只预览建议，采纳后可逐字段填入草稿，维护者决定受众并提交审核。

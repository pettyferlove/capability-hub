# 反馈研判与资源审计

`feedback-triage` 与 `resource-audit` 定义在 `packages/hub-agents`，运行、租约、暂停恢复与 SSE 复用 [AI 框架](ai-framework.md)。Application 的 `AgentEvidenceService` 提供业务证据，框架不依赖 Hub。没有新增 Worker、数据库表或迁移。

## 发起与权限

资源审计输入为 `{version_id}`，反馈研判为 `{version_id, feedback_id}`，不提交资源正文。提交、模型请求、工具执行、记录读取及 SSE 推送均重新核验账号、AI 权限和资源权限。反馈还须满足原有提交者或维护者可见规则，并匹配目标版本。候选沿用维护者与对应审核者的审查权限；封禁资源和撤销版本不接受研判。

已配置模型且发起人具有 `ai:execute` 时，上传或同步完成固定快照、反馈上报和发布申请（含通用提名）在原业务事务中自动创建任务；否则保留原业务流程。同一发起人、操作和固定目标复用已有任务，重扫、发布申请和并发自动触发不会重复排队；失败任务不自动重试，可手动发起新研判。队列写入失败回滚本次业务；账号失效或资源权限不足时跳过自动审计。

业务工作区按操作、固定版本和反馈 ID 查找当前用户任务。审核者可发起自己的审计；具有 `ai:inspect` 且知道执行 ID 的人员按框架规则读取他人的任务，不能代答或取消。

## 自主取证

| 工具                | 能力与边界                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `resource_overview` | 类型、固定版本摘要、入口文件，不加载正文                                                         |
| `list_files`        | 分页目录、大小、SHA-256、可执行标记，每页最多 100 项                                             |
| `read_file`         | 固定版本按行读取；每次最多 200 行、24,000 字符；超过 512,000 字节或非 UTF-8 文本时明确返回不可读 |
| `search_files`      | 字面文本定位；每次检查 10 个文件的前 200 行，返回游标和未完整检查文件；引用前仍需显式读取        |
| `scan_findings`     | 固定版本的静态扫描状态、规则与发现项                                                             |
| `compare_release`   | 与当前发布比较新增、修改、删除文件，不隐式读取正文；基线权限独立核验                             |
| `mcp_declarations`  | MCP 安装选项、工具声明和描述 Schema                                                              |
| `read_feedback`     | 目标反馈的观察、预期、复现、证据和建议，仅反馈研判提供                                           |

Skill 从 `SKILL.md` 开始，按引用读取其他文件；MCP 从 `server.json` 开始，检查安装、权限、变量、网络目的地和工具声明。未读取入口文件或目标反馈时不能形成报告。工具不接受任意版本、宿主路径、Shell 命令或网络 URL。资源与反馈是不可信证据，不能改变授权或系统指令。

此批 MCP 审计为静态审计，不连接声明远端、不安装软件包、不执行其中的工具，报告始终列明范围。框架独立提供的受信 MCP 只读工具接入不代表被审计资源通过了动态验证。

调查最多 64 个 Agent 步骤，仍受实例级请求、工具、时间、事件预算约束。预算由 [AI 框架](ai-framework.md) 统一定义。

## 报告与人工决定

调查实时展示活动，再形成结构化摘要、风险、发现、建议、文件行号引用、局限和处理说明。引用必须完全落在实际读取过的单段范围，否则失败。成果额外记录内容摘要、已读文件数及行号范围；引用范围有效不等于模型解释一定正确。

资源审计操作版本为 `3`，反馈研判为 `2`。报告整理使用框架显式注入的 Schema 约束，并作为「整理研判报告」阶段展示；格式失败显示输出校验错误，不误报为工具调用失败。旧版本任务不套用新提示规则恢复，需要发起新任务。

报告先保存为 `assessment` 成果，再暂停为 `human-review`。发起人明确采纳或不采纳并填写可选意见；不采纳正常结束并保留记录。采纳审计不批准发布、不改变扫描状态，不代替告警接受理由或独立人工审核。

反馈研判对有维护权限的发起人提供可选写回：采纳后改为 `in_progress`，以人工意见或报告建议作为处理说明，不自动解决或关联修复版本。写回使用调查开始时的 feedback revision，恢复时重新检查权限；人工已更新则拒绝旧结果。业务更新和效果回执共用事务，恢复不重复写入。未勾选写回则不改反馈状态。

## 页面行为

校验、发布申请、审核详情和反馈详情复用同一面板，并订阅该目标已有任务。收起不取消任务、不停止订阅、不丢失确认草稿。快速采纳沿用已填意见、交互修订和幂等键。反馈研判采纳后，同一修订的建议填入维护者的空白处理说明草稿，已有内容由维护者选择替换；保存后可在反馈详情顶部查看。没有活动任务且已配置模型时，可以按当前模型和资源目标重新发起。等待人工确认时加载完整报告和表单，回答后继续订阅。文件读取活动展示路径和请求行号。

资源审计必须给出发布建议，包括分类、有效场景 ID、检索关键词和共享目的。调查可用 `publication_scenarios` 查阅有效场景。发布页以当前用户同版本已完成审计中最近一次采纳为准，核对版本与内容摘要后填写可编辑草稿。保留本次已编辑字段；待确认时只预览建议，采纳后可逐字段采用，关键词合并去重。可见范围和最终提交仍由使用者决定。历史报告缺少发布建议时需重新发起。

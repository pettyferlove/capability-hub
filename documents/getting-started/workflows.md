# 资源使用与发布

## 使用资源

首页可直接描述任务，不必先知道资源名或类型。目录卡片显示适用场景，详情可看该版本的场景说明，无需先筛选。关键词检索只匹配可见发布；中文按有效词、连续单字按相邻双字匹配，完整 slug 直接命中。

配置默认模型后，问题连同提问者可见的发布卡片交给模型；超出预算时先按字面相关度选候选。等待时显示已读资源数、回答起草和核对进度，可以停止。服务端复核可见性后才显示回答和固定版本；「AI 判断」是推荐理由，「发布信息写明」是核对过的原文。未配置模型时只做关键词匹配；模型超时、限流或输出无效会提示，不静默降级。

顶部「帮我找」开始新检索。空输入时，完整可见的轮播示例可直接发送；显示不全则先填入草稿。快捷问题只填入，不发送。结果下「继续追问」保留本轮条件；选方向、改条件不调模型。每次提问至多一次出站，不保存问题、回答或聊天历史。身份变化清空对话，模式变化须确认后再发送。

本轮展示多个 Skill 时，点「批量获取 Skill」可全选或只保留想要的项：下载一个 ZIP，或选好客户端，一次复制安装命令或交给 Agent 的指令。MCP 仍逐项配置。每项锁定结果里的版本，上新不换版；清单只包含本轮展示的 Skill，不是所有命中项。

单项点「查看接入方式」打开固定版本；撤回或无权读取时不回落最新版。打开安装页不会预发票据、解密共享密钥或生成含密钥的配置。Skill 内容优先展示根目录 `README.md`，无法预览时展示 `SKILL.md`。

公开 Skill 可匿名安装；未连接 MCP 时，安装团队 Skill 前先运行 `capability-hub login --url https://hub.example.com`：

```sh
capability-hub add NAME --version VERSION --url https://hub.example.com --to .agents/skills --dry-run
```

核对预览后去掉 `--dry-run`；替换已有目录须显式 `--replace` 并保留备份，CLI 不执行脚本。「交给 Agent」用 `名称@完整版本号` 指定 Skill。已授权的 Agent 在同一 Hub 用 `get_asset_version` 解析版本，再按 `install_skill` 返回的命令预览，无需手填 UUID 或另外登录 CLI。

定期运行 `capability-hub outdated` 检查当前项目的预设技能目录，或重复传入 `--to`。有更新时先执行建议的 `--dry-run`，确认后再替换；不可用、弃用或本地已修改时先复核。检查不改写安装或旧来源记录。

MCP 可用 `mcp-config NAME --version VERSION --client CLIENT --option OPTION_ID` 输出配置。若当前发布不可读但历史 MCP 仍可读，在固定版页面预览配置或通过 Hub MCP 生成。保留已有配置，在目标客户端设置变量并验证连接；Skill 的 `--to` 目录见 [Agent 客户端接入](../reference/agent-clients.md)。

Hub 自身也可通过对话接入：在“连接你的 Agent”页选择客户端与范围，复制 Hub 接入指令交给 Agent。这一步不依赖已连接的 Hub MCP，凭据由客户端或接入助手保存，用户仅在浏览器确认授权；说明链接与 CLI 用法见 [首次接入说明](../reference/agent-clients.md#通过对话接入-hub-自身)。

## 上传与来源

Skill 上传表单的「确认资产信息」区域提供「使用时需要 API Key」选项，默认不勾选；已有资产新版本预填当前声明。全部或部分功能需要使用者自行配置 API Key 时均可勾选，并在 Skill 文档中说明配置方式。新版本的声明先随接收记录保存，提交审核时可再次调整，审核通过后更新目录标签。Git 来源也可在提交审核时声明。

维护者还可在资产维护或详情页的维护区域直接调整当前使用提示。勾选后，目录卡片和详情显示「需 API Key」标签；未勾选不显示反向标签。此项不保存密钥，不代表配置或验证结果，也不改变内容版本和发布受众。

上传 Skill ZIP 或 MCP server.json，选定团队、资源名及固定版本。MCP 表单可生成远程 HTTP 或固定 npm 版本描述，只解析命令而不执行。

已有 Git 资产的新内容通过来源同步接收，不能在上传表单中选作手工上传目标。

Git 来源先在个人中心维护凭据，再登记仓库、分支和精确目标。SSH 需要私钥及独立确认的服务器主机公钥。同步后检查具体提交和接收结果；保存来源配置或扫描通过都不会自动发布。

## 发布与审核

维护者核对内容、用途、分类、关键词和受众。选「场景」时可复用已有条目，或填写新场景的名称和适用说明。新定义随发布申请交独立平台审核，通过后供其他资产复用。审核者还需逐条接受 warning 或说明理由退回。

Skill 审核详情中的「认证与使用要求」展示提交时固定保存的 API Key 声明，并对照上次发布声明。审核员可直接打开 SKILL.md，结合引用文件核对认证方式、配置步骤和凭据用途。未声明 API Key 需求不代表没有登录、OAuth 等独立认证流程，静态扫描通过也不代表认证流程已验证；不一致时退回维护者修正。声明纳入审核摘要和发布记录，后续资产维护不会改写历史记录。

跨团队和通用资源需平台审核，提交者及提名对应来源共享者不得自审。审核者不在分发受众中时需再次确认；发布回执显示受众，可直接打开本次审核记录。

旧申请失效后不可批准。提交者可撤回，维护者从「查看原接收记录」按需重扫并重提。用当前规则的证据重提同一版本，会同时将旧规则的待审申请标为失效。

资源可推荐和提名通用；提名不改变原受众。弃用仍保留内容，封禁或撤销会限制后续分发。回退仍走新的独立审核。

### 同一资产的后续更新

「分享 → 维护资产」默认按业务变动倒序，可切换名称升序、搜索或筛选。「需要处理」仅列当前有权处理的事项。Git 同步若内容与来源修订均和当前发布一致，只保留校验结果；仅换规则重验不刷新排序。上传来源点「更新版本」，Git 来源点「前往 Git 同步」；弃用或封禁时不可更新。

接收详情展示「当前发布 → 本次快照」的版本号、内容摘要与点阵；审核页面展示「提交时发布 → 申请发布」。新点阵的描边表示图案发生变化，具体内容差异仍以文件审查为准；图案相同不作为内容相同的证明，内容是否变化按完整摘要判断。相同内容另行申请分发时，明确提示核对分类、受众和使用要求。

提交审核绑定接收详情展示的发布基线，不在提交时静默改用最新发布；若期间已有其他发布，刷新详情后重新核对再提交。历史审核始终使用申请中冻结的基线，不随当前发布变化。校验、待审核与审核通过发布是不同阶段，提交或上传不会直接替换目录内容。

「管理」展示当前、历史、未发布和已撤销版本。未发布版本可单独删除；资源从未正式发布时可整体删除。待审申请须先撤回，处理中任务须结束；两种删除均填写原因并二次确认，保留审计。已发布版本只能撤销，回退历史内容仍需审核。Git 资源删除同步解绑，需来源管理权限；删除版本保留资源。维护与分发权限独立。

### 查看详情与跟进反馈

从维护资产、接收记录等页面打开目录详情时，详情叠加在原页面上；关闭或浏览器后退会回到原入口，保留当前筛选和页面状态。直接打开资产链接则以发现页为背景。浏览器刷新保留本次历史条目的来源信息，分享链接不携带来源页面状态。

资产详情顶部提供「问题与建议」操作与同名一级页签。维护列表通过「管理」打开抽屉，切换「问题与建议」跟进反馈。反馈区按列表、详情、提交表单切换；列表支持状态筛选，详情可返回原筛选结果，空列表不显示无效分页按钮。

提交表单先填写标题、业务目标、预期和实际情况，复现步骤与证据放在可选补充区。返回列表会保留当前页面中的草稿，提交成功后直接展示新反馈详情；关闭资产详情或刷新页面不会保存未提交草稿。提交仍需脱敏确认，处理结果保存后显示明确回执。反馈可见范围和维护权限保持原有规则。

### 使用 Agent 研判

维护者在「校验与发布申请」采纳分类、关键词和共享目的建议。有权限且已配置模型时，查看待审详情自动生成首份简报，打开「审核决定」自动发起首次版本审计。已有任务不自动重跑，失败可手动重试。采纳审计建议会填入空白审核意见，已有意见可手动追加。反馈详情标出共享研判负责人；有相应 AI 权限的同一资产维护者可回看，负责人可采纳并写入处理说明。任务归属和权限见 [Agent 执行与权限清单](../design/ai-framework.md#当前操作与权限)，写回条件见 [业务 Agent](../design/business-agents.md#报告与人工决定)。

## 反馈平台问题

从顶栏、个人菜单或命令面板打开「反馈问题」。可截取当前标签页，也可粘贴、拖入或选择附件。截图会隐藏面板并自动遮挡已标记的敏感区，也可用不透底的马赛克手动遮挡。提交前核对图片，逐项选择诊断。收起保留草稿，刷新只保留文字；登录失败可复制诊断信息。

在「个人中心 → 我的反馈」查看进展、留言或关闭。平台处理人员到「运营中心 → 平台反馈」认领、回复和更新状态；内部备注仅处理人员可见。资源内容问题仍从资源详情的「问题与建议」提交。

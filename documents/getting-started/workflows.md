# 资源使用与发布

## 使用资源

网页和 MCP 只检索可见发布的名称、标签和描述。中文需求按有效词匹配，连续单字按相邻双字检索。含中文的多词查询至少命中两词且覆盖半数，完整的资源 slug 可直接命中。`Node.js` 等技术名保留完整，单独输入一个汉字时可按该字查询。

公开资源可匿名阅读、下载，或复制“请安装这个 Skill/MCP”指令。团队资源需相应权限，网页、CLI 和 Hub MCP 各自授权。

CLI 安装固定版本并指定目录：

```sh
capability-hub login --url https://hub.example.com
capability-hub search "关键词"
capability-hub add NAME --version VERSION --to .agents/skills --dry-run
capability-hub add NAME --version VERSION --to .agents/skills
```

查看 dry-run 的文件及本地差异后再安装。已有目录需要显式 --replace，旧内容会保留在输出所示备份目录。CLI 不执行资源脚本。

MCP 用 `mcp-config NAME --version VERSION --client CLIENT --option OPTION_ID` 输出配置。支持的客户端、Skill 目录与官方依据见 [Agent 客户端接入](../reference/agent-clients.md)。设置本机所需变量，保留客户端原配置，并在目标客户端自行完成连接核验。Skill 的 `--to` 应选用目标客户端支持的目录。

Hub 自身也可通过对话接入：在“连接你的 Agent”页选择客户端与范围，复制 Hub 接入指令交给 Agent。这一步不依赖已连接的 Hub MCP，凭据由客户端或接入助手保存，用户仅在浏览器确认授权；说明链接与 CLI 用法见 [首次接入说明](../reference/agent-clients.md#通过对话接入-hub-自身)。

## 上传与来源

Skill 上传表单的「确认资产信息」区域提供「使用时需要 API Key」选项，默认不勾选；已有资产新版本预填当前声明。全部或部分功能需要使用者自行配置 API Key 时均可勾选，并在 Skill 文档中说明配置方式。新版本的声明先随接收记录保存，提交审核时可再次调整，审核通过后更新目录标签。Git 来源也可在提交审核时声明。

维护者还可在资产维护或详情页的维护区域直接调整当前使用提示。勾选后，目录卡片和详情显示「需 API Key」标签；未勾选不显示反向标签。此项不保存密钥，不代表配置或验证结果，也不改变内容版本和发布受众。

上传 Skill ZIP 或 MCP server.json，选定团队、资源名及固定版本。MCP 表单可生成远程 HTTP 或固定 npm 版本描述，只解析命令而不执行。

已有 Git 资产的新内容通过来源同步接收，不能在上传表单中选作手工上传目标。

Git 来源先在个人中心维护凭据，再登记仓库、分支和精确目标。SSH 需要私钥及独立确认的服务器主机公钥。同步后检查具体提交和接收结果；保存来源配置或扫描通过都不会自动发布。

## 发布与审核

维护者核对内容、用途、分类、关键词和受众。选「场景」时可复用已有条目，或填写新场景的名称和适用说明。新定义随发布申请交独立平台审核，通过后供其他资产复用。审核者还需逐条接受 warning 或说明理由退回。

Skill 审核详情中的「认证与使用要求」展示提交时固定保存的 API Key 声明，并对照上次发布声明。审核员可直接打开 SKILL.md，结合引用文件核对认证方式、配置步骤和凭据用途。未声明 API Key 需求不代表没有登录、OAuth 等独立认证流程，静态扫描通过也不代表认证流程已验证；不一致时退回维护者修正。声明纳入审核摘要和发布记录，后续资产维护不会改写历史记录。

public 扩大到匿名用户，organization 扩大到所有有效登录用户；跨团队和通用资源要求平台范围审核。提交者及提名对应来源共享者不能自行批准。审核上下文变化后需重新核对，页面不会自动重试旧决定。

资源可推荐和提名通用；提名不改变原受众。弃用仍保留内容，封禁或撤销会限制后续分发。回退仍走新的独立审核。

### 同一资产的后续更新

在「分享 → 维护资产」按名称、类型或状态查找资产。卡片展示当前发布版本、待审核申请和最近接收记录；上传来源可直接点击「更新版本」，自动选中原资产及 Skill/MCP 类型。Git 来源从「前往 Git 同步」继续同步。弃用或封禁期间不提供新版本入口。

接收详情展示「当前发布 → 本次快照」的版本号、内容摘要与点阵；审核页面展示「提交时发布 → 申请发布」。新点阵的描边表示图案发生变化，具体内容差异仍以文件审查为准；图案相同不作为内容相同的证明，内容是否变化按完整摘要判断。相同内容另行申请分发时，明确提示核对分类、受众和使用要求。

提交审核绑定接收详情展示的发布基线，不在提交时静默改用最新发布；若期间已有其他发布，刷新详情后重新核对再提交。历史审核始终使用申请中冻结的基线，不随当前发布变化。校验、待审核与审核通过发布是不同阶段，提交或上传不会直接替换目录内容。

「版本与管理」区分当前、历史、未发布和已撤销版本，可从历史版本申请回退。维护设置提供使用提示、生命周期和来源操作；无内容版本、接收均失败或取消且无处理中作业的未封禁上传资源可选择「删除错误资源」，填写原因后二次确认，释放名称并保留审计。维护与分发权限独立，无目录访问权仍可管理版本。

### 查看详情与跟进反馈

从维护资产、接收记录等页面打开目录详情时，详情叠加在原页面上；关闭或浏览器后退会回到原入口，保留当前筛选和页面状态。直接打开资产链接则以发现页为背景。浏览器刷新保留本次历史条目的来源信息，分享链接不携带来源页面状态。

资产详情顶部提供「问题与建议」操作与同名一级页签，无需滚动到说明末尾。维护卡片也可直接打开反馈页签，版本记录、问题与建议、维护设置分别呈现。反馈区按列表、详情、提交表单切换；列表支持状态筛选，详情可返回原筛选结果，空列表不显示无效分页按钮。

提交表单先填写标题、业务目标、预期和实际情况，复现步骤与证据放在可选补充区。返回列表会保留当前页面中的草稿，提交成功后直接展示新反馈详情；关闭资产详情或刷新页面不会保存未提交草稿。提交仍需脱敏确认，处理结果保存后显示明确回执。反馈可见范围和维护权限保持原有规则。

### 使用 Agent 研判

维护者在「校验与发布申请」采纳分类、关键词和共享目的建议。审核员在待审页底栏发起研判，按风险提示核对依据。「记录审核决定」中采纳的版本审计建议会填入空白意见，已有意见可手动追加。反馈详情会标出共享研判的负责人，有相应 AI 权限的同一资产维护者可打开只读报告。负责人采纳反馈研判时可选择写入处理说明。任务归属和权限见 [Agent 执行与权限清单](../design/ai-framework.md#当前操作与权限)，写回条件见 [业务 Agent](../design/business-agents.md#报告与人工决定)。

# 测试策略

## 分层

| 目录        | 验证对象                                                     | 方法                                |
| ----------- | ------------------------------------------------------------ | ----------------------------------- |
| unit        | 规范 JSON、路径、版本、密码/密文/游标、内容校验、配置        | 有效输入和恶意/边界输入的可观察结果 |
| integration | 真实 SQLite、用例、HTTP、MCP SDK、CLI 子进程、备份与作业竞争 | 独立临时实例，真实协作对象          |
| components  | 表单、键盘、弹层、查询和会话竞争                             | jsdom、Testing Library、user-event  |
| external    | PostgreSQL、受限账号 MinIO、SSH Git 及完整业务链             | 本机 Docker，真实协议与独立资源     |
| support     | 共享实例、内容、存储、HTTP/DOM 和外部资源夹具                | 隔离创建、结束清理                  |

```sh
pnpm test
pnpm test:external
```

runner 发现文件为空会失败；默认只包含 unit、integration、components。外部 runner 校验本机 Docker Unix socket，生成临时身份和随机项目，等待健康后执行，最终清理自身容器、卷、网络和构建镜像。不能使用远程生产 Docker。

## 必须守住的行为

- 提交者和来源共享者不能自审；候选读取严格匹配申请版本。
- 审核竞争、修订/摘要/上下文变化、未知/重复告警接受项不产生发布。
- 当前受众收窄、封禁和撤销同步影响历史链接及缓存。
- 消费令牌不能越界到个人/管理接口，无效 Bearer 不能匿名降级，Cookie 写入校验 CSRF。
- 事务失败、嵌套捕获、未等待和迟到写入整体回滚；租约接替、取消和到期不能被旧执行者覆盖。
- 内容按实际字节校验，损坏对象不覆盖修复；CLI 明确覆盖、备份及提交前目标变化可观察。
- 查询和会话的迟到响应不能覆盖当前状态或恢复已退出身份；发布策略完整呈现多受众，账号重新启用不复活已撤销令牌。

jsdom 夹具将异步事件中的未捕获异常转为测试失败；只为其不实现的布局接口提供挂载所需的空实现，不据此验收滚动或布局。

测试描述结果，避免断言私有调用次数、实现字符串或无关 DOM 类名。竞争测试用明确同步点，等待全部 Promise 和清理；不依赖“睡一会应该成功”。不设数字覆盖率门槛，也不以测试数量替代风险评估。

## 证据边界

DOM 测试不能证明浏览器布局、滚动、动画和可访问树的真实表现。HTTP/官方 MCP SDK 测试不能证明所有 Agent 产品已支持当前协议。外部测试不能证明生产网络、反向代理、备份存储或真实仓库授权。

报告中分别列出静态、默认测试、外部、镜像、浏览器和目标客户端验证。没有执行的项目标为未验证，不用模拟页面或跳过鉴权补造证据。

## 工程静态检查

脚本的职责和入口见[脚本分类](scripts.md)。

`pnpm check` 串联架构、文档、迁移、ESLint、格式、类型/构建与默认测试。检查工具本身也需要行为测试，防止检查通过仅说明正则没有命中。

- 架构检查使用 TypeScript 语法树与项目模块解析选项，检查声明依赖、分层、公共导出、浏览器入口、命名与显式 any。静态运行时导入图支持无扩展名路径，纯类型导入/重导出不产生运行时环；字面量动态导入和 require 仍检查依赖边界，动态加载不纳入静态运行时环。任意动态表达式的目标不在静态可解析范围内。
- 文档检查复用 Markdown 语法解析，检查仓库内目标存在性；支持参考式链接、编码路径和查询参数，忽略代码块/行内代码中的示例。编码错误和越界有文件行号，不发网络请求，不验证段落锚点。
- 数据库检查校验 journal 与 SQL/快照对应关系，再在临时副本运行锁定版本的 Drizzle，并比较整个迁移树摘要。它验证生成快照与 Schema 一致，不证明原生触发器、STRICT 或延迟外键的数据库运行行为；这些由数据库集成和外部测试验证。
- 颜色策略通过 TypeScript 语法树提取样式上下文的字面量，通过 PostCSS 解析 CSS 声明和主题。注释、普通文案、URL 锚点不应被误报为颜色。动态拼接或运行时传入的颜色仍需要界面审查；对比度测试只验证列出的主题色对。
- ESLint、Prettier 和 TypeScript 沿用各自语法工具；版本、项目范围和生成物排除项必须与工作区一致。禁止为通过检查而关闭实际失败的规则或改写已应用的迁移历史。

变更静态检查时，至少覆盖真实缺陷、相近合法输入、格式变体以及失败后的可操作提示。内容规则调整还必须验证告警接受流程和规则版本失效机制，详见[内容静态检查](../design/content-lifecycle.md#静态检查的判定与边界)。
